# Contributing to AKOREDE VITA

Thank you for your interest in the project.

## Before contributing

- Read the project [README](README.md), [architecture](docs/ARCHITECTURE.md), and [roadmap](docs/ROADMAP.md).
- Check the selected upstream project's contribution rules before changing or redistributing upstream-derived code.
- Keep changes small and explain their purpose.

## Development workflow

1. Open or create an issue describing the problem or proposed change.
2. Identify whether the change belongs to the product layer, a platform adapter, or the upstream emulation core.
3. Add or update tests where practical.
4. Document build and test steps.
5. Submit a pull request with a concise summary and test evidence.

## Legal and security requirements

- Preserve all applicable copyright and licence notices.
- Do not submit proprietary firmware, encryption keys, copyrighted game files, credentials, or personal data.
- Do not claim compatibility or successful testing without reproducing it.
- Disclose security concerns privately to the repository maintainer rather than publishing exploit details.

## Learning-friendly contributions

Explanations and documentation improvements are welcome. New contributors should be able to understand why a change exists, how to build it, and how it was tested.
